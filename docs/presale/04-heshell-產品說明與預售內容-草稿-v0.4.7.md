## 2. 分析與標記

### 可保留內容（結構清楚、可作為草稿基礎）

- **產品本質**：客戶端安全殼層（Secure Client-Side Shell）+ 外部模型路由中繼。**不訓練、不微調基礎語言模型；不實作同態加密密碼學基元**，而是消費外部或本機 HE API。
- **L0–L3 能力分級（README 明令禁止混稱）**：
  - L0 傳輸層加密（TLS）：**非本產品**，不列為隱私賣點。
  - L1 指定 HE API 密文運算（固定電路：Embedding 比對、距離計算、數值評分與分類）：**本期交付**。
  - L2 端點密文模型推論：**條件交付**，僅限端點有明確且經簽章的能力宣告時才路由。
  - L3 任意閉源商用 LLM 直接處理密文即時生成：**非現行科技，嚴禁承諾，不列入 v1 驗收與 Roadmap**。
- **FAIL-CLOSED**：端點不支援 L1/L2 時直接拒絕（`HE_002`），**不提供、也不得自動降級為明文**。
- **USB 與金鑰（v0.4／v0.4.1／v0.4.2 依主 PMO 2026-11-13 答覆改寫）**：HEShell 自 HE Provider 取回一把加密私鑰，私鑰於本機當場組合為複合金鑰（Combined Key）後存放於 USB；「在本機加密」為先將金鑰組合成當前最新的加密金鑰，再以其加密使用者輸入。「HE Provider 不能接觸到這把私鑰」（已確認）。「不經上傳、不做雲端備份」仍成立：對外傳輸的是複合金鑰（CombineKey）的組件，而非使用者 AI 提問的文字。USB 位於虛擬機的 USB 埠；使用者可自行備份 USB，但遺失不補發。不做雲端備份。原 README「`sk` 由 USB 生成、留在 USB 邊界／永不出界」之說法與答覆不一致，不再作為可保留內容。USB 拔除觸發中止傳輸、清除畫面、記憶體零值抹寫、銷毀金鑰句柄、禁止回復（README 原設計，保留）。
- **介面規範**：**嚴禁虛假的逐字打字機串流**；必須以階段指示器呈現批次等待。原 README 設計為「金鑰封裝中 → 密文傳輸中 → 密文同態運算中 → 密文下載中 → 本機解密驗證」；因結果以明文回傳，建議改為「金鑰封裝中 → 密文傳輸中 → 密文同態運算中 → 接收結果」，階段名稱是否再調整 [待確認]。
- 模組：`desktop-ui`（Tauri/Rust）、`usb-sentinel`、`he-client-sdk`、`zero-leak-router`、`secure-mem`（mlock / memset_s）、`sanitized-logger`。
- 錯誤碼 `HE_001`～`HE_006`、威脅模型 TM-01～TM-06、驗收 Gate 1～5（明言不以「串接公有 API 秒回」為驗收標準）。

## 3. 產品概述

HEShell 是 AEGIS（`aegis.expert`）規劃中的本機 AI 安全殼層：使用者在桌面殼層輸入內容；依主 PMO 2026-11-13 答覆（經視覺內容規劃 Bot 轉達），明文不送往外部 HE Provider，HEShell 自 HE Provider 取回一把加密私鑰，私鑰於本機當場組合為複合金鑰（Combined Key）後存放於插在本機的專用 USB；HE Provider 不能接觸到這把私鑰，再以組合成的當前最新加密金鑰加密使用者輸入。加密後的輸入送往有明確能力宣告的端點運算；**結果以明文回傳**（主 PMO 2026-11-13 補充答覆（經視覺內容規劃 Bot 轉達））。HEShell 為已與 S0 單向輸入加密架構（Legacy）不同的改版，S0 仍嚴格廢棄；HEShell 採 L0–L3 分級，不以 S0–S3 評級。HEShell 本身不訓練模型，也不自行實作密碼學基元，它負責的是金鑰邊界、密文路由與本機明文防護。

它的核心規則是「不支援就不送」：目標端點若沒有經簽章的 L1／L2 密文能力宣告，請求直接被拒絕，系統不會詢問是否改送明文。v1 交付範圍為 L1（固定電路的密文運算，如 Embedding 比對、距離計算、評分與分類）；L2 端點密文模型推論為條件交付；「任意商用 LLM 直接處理密文並即時生成」（L3）不是現行技術，不在承諾範圍內。由於密文推論需要批次等待，介面以階段指示器呈現進度，不模擬逐字串流。

## 4. 核心特性與功能（可驗證者優先）

以下摘自 README，實作完成度均為 [待確認]。

1. **能力分級路由（`zero-leak-router`）**：檢查端點經伺服器私鑰簽章之 Capability Manifest（支援方案 CKKS/BFV/TFHE、最高乘法深度、密文 I/O 支援證明）；非 L1/L2 一律阻斷（`HE_002`）。

5. **本機記憶體防護（`secure-mem`）**：以 `mlock`／`VirtualLock` 防止明文寫入 Swap/Pagefile。
6. **零明文日誌（`sanitized-logger`）**：僅記錄延遲、密文位元組數、錯誤碼、金鑰識別雜湊；封鎖 Full Memory Dump。
7. **誠實的等待介面**：階段指示器取代逐字串流，明示批次等待時間。
8. **HE API 契約**：Session 初始化、本機加密、推論派送、結果輪詢（含 `proof_of_execution`）、本機解密；錯誤碼 `HE_001`～`HE_006`。（README 原設計；結果以明文回傳，「本機解密」步驟是否保留 [待確認]）

## 6. HE API 介面契約

殼層不自行實作密碼原語，依下列契約消費外部 HE 服務或本機 HE 模組（欄位值皆為示例）：

- A. `POST /v1/he/session/init`：建立會話（scheme、params、client_id）；回傳 session_id、public_key_ref、所需評估金鑰。自 HE Provider 取回加密私鑰是否經此 API 及其欄位 [待確認]。
- B. 本機加密：自 HE Provider 取回一把加密私鑰，私鑰於本機當場組合為複合金鑰（Combined Key）後存放於 USB；先將金鑰組合成當前最新的加密金鑰，再以其加密使用者輸入；明文不送往外部 HE Provider；HE Provider 不能接觸到這把私鑰（主 PMO 2026-11-13 答覆）。
- C. `POST /v1/he/inference/dispatch`：送出密文、評估金鑰、`target_model_capability`、`max_computation_depth`；回傳 task_id 與 `estimated_latency_sec`（範例值，非承諾）。
- D. `GET /v1/he/inference/result/{task_id}`：取回密文結果、consumed_depth、proof_of_execution。
- E. 本機解密：README 原設計為僅 USB 在位時執行、USB 離線則硬體拒絕並拋錯；依主 PMO 2026-11-13 補充答覆結果以明文回傳，本步驟及 D 之「取回密文結果」如何調整 [待確認]。

## 7. 路由規則（FAIL-CLOSED）

1. **絕不自動降級**：端點不支援密文推論時，不提供「改以明文發送？」選項，請求直接無效。
2. **能力宣告白名單**：端點須提供經伺服器私鑰簽章之 Capability Manifest，載明支援方案（CKKS / BFV / TFHE）、最高乘法深度、密文 I/O 支援證明。
3. **明文審查閘門**：出境 Payload 若非標準密文結構或含自然語言明文字元，Socket 立即關閉。

## 9. 開發里程碑與驗收

里程碑（內部排程，非對外交期）：M1 硬體金鑰介面與安全記憶體 → M2 外部 HE API 整合 → M3 零洩漏路由器與 UI 狀態機 → M4 端到端密文推論整合與故障驗收。
