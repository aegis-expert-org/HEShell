## 2. 分析與標記

### 可保留內容（結構清楚、可作為草稿基礎）

- **產品本質**：客戶端安全殼層（Secure Client-Side Shell）+ 外部模型路由中繼。**不訓練、不微調基礎語言模型；不實作同態加密密碼學基元**，而是消費外部或本機 HE API。
- **L0–L3 能力分級（README 明令禁止混稱）**：
  - L0 傳輸層加密（TLS）：**非本產品**，不列為隱私賣點。
  - L1 指定 HE API 密文運算（固定電路：Embedding 比對、距離計算、數值評分與分類）：**本期交付**。
  - L2 端點密文模型推論：**條件交付**，僅限端點有明確且經簽章的能力宣告時才路由。

## 3. 產品概述

HEShell 是 AEGIS（`aegis.expert`）規劃中的本機 AI 安全殼層：使用者在桌面殼層輸入內容，由插在本機的專用 USB 硬體管理本次對話的秘密金鑰，輸入在本機加密為同態加密（HE）密文後，才送往有明確能力宣告的端點運算；回傳的密文結果只在 USB 在位時於本機解密顯示。HEShell 本身不訓練模型，也不自行實作密碼學基元，它負責的是金鑰邊界、密文路由與本機明文防護。

它的核心規則是「不支援就不送」：目標端點若沒有經簽章的 L1／L2 密文能力宣告，請求直接被拒絕，系統不會詢問是否改送明文。v1 交付範圍為 L1（固定電路的密文運算，如 Embedding 比對、距離計算、評分與分類）；L2 端點密文模型推論為條件交付；「任意商用 LLM 直接處理密文並即時生成」（L3）不是現行技術，不在承諾範圍內。由於密文推論需要批次等待，介面以階段指示器呈現進度，不模擬逐字串流。

## 4. 核心特性與功能（可驗證者優先）

以下摘自 README，實作完成度均為 [待確認]。

1. **能力分級路由（`zero-leak-router`）**：檢查端點經伺服器私鑰簽章之 Capability Manifest（支援方案 CKKS/BFV/TFHE、最高乘法深度、密文 I/O 支援證明）；非 L1/L2 一律阻斷（`HE_002`）。
2. **FAIL-CLOSED／禁止明文降級**：無「改送明文後備」路徑；出境封包若含自然語言明文字元即強制關閉 Socket（`HE_003`）。
3. **USB 硬體金鑰邊界（`usb-sentinel`）**：硬體憑證與非對稱挑戰握手；每次對話產生 Session；`sk` 不經 API 上傳、禁止雲端備份。
4. **拔除即清除**：USB 拔除時中止傳輸與解密、白屏、零值抹寫明文緩衝區、銷毀金鑰句柄、禁止自快取還原。README 工程門檻為 50 毫秒內完成 [待確認]。
5. **本機記憶體防護（`secure-mem`）**：以 `mlock`／`VirtualLock` 防止明文寫入 Swap/Pagefile。
6. **零明文日誌（`sanitized-logger`）**：僅記錄延遲、密文位元組數、錯誤碼、金鑰識別雜湊；封鎖 Full Memory Dump。
7. **誠實的等待介面**：階段指示器取代逐字串流，明示批次等待時間。
8. **HE API 契約**：Session 初始化、本機密文封裝、推論派送、結果輪詢（含 `proof_of_execution`）、本機解密；錯誤碼 `HE_001`～`HE_006`。

| 級別 | 定義 | 本產品狀態 |

| L0 | 傳輸層加密（TLS／HTTPS），伺服器端明文 | 非本產品，不作為隱私賣點 |
| L1 | 指定 HE API 固定電路密文運算 | 本期交付 |

## 6. 差異化定位

**同法人（AEGIS）相鄰產品**

- **vs. FHE AI NAS（with USB）**：兩者都用 USB 金鑰，最容易混淆。HEShell 是**本機殼層與路由器**，不擁有模型、不儲存知識庫，把密文送往具 L1/L2 能力的外部端點；FHE AI NAS 是**地端運算與知識庫節點**，自帶本地 SLM/LLM 與 RAG，v1 為 S1（推論熱路徑有受控短暫解密點）。兩者的分級命名也不同（L0–L3 vs. S0–S3），對外不可混用。

- **與「前代套殼」的關係**：見第 2 節，[待確認] 後再決定對外是否提及。

**跨法人**

- **vs. AllView FHE Social、VeilProof 隱證**：兩者是 AllView 的應用層產品（社群、商務推演）；HEShell 是 AEGIS 的客戶端安全基礎元件。若 AllView 產品採用 AEGIS 元件，屬協作，不改變各自歸屬。

**相對於一般「加密 AI 聊天」工具**：差異在於明訂 L0 不算隱私、端點不支援就拒絕、介面不假裝即時，並把 L3 明確排除，而不是在速度上競爭。

### 短文案（資安要求高的組織）

多數「加密 AI」只加密了傳輸線路，伺服器端仍看得到明文。HEShell 把解密金鑰留在你手上的 USB 硬體裡，輸入在本機加密後才送出；目標端點若不能處理密文，請求就直接被拒絕，系統不會替你改送明文。拔掉 USB，畫面立即清空、記憶體中的明文被抹除。

### 短文案（誠實說明速度）

密文運算比明文慢得多，這是目前技術的事實。HEShell 不會用逐字跳出的動畫假裝即時，而是清楚顯示每個階段：金鑰封裝、密文傳輸、同態運算、密文下載、本機解密。你知道系統在做什麼，也知道為什麼要等。

### 賣點句

- 不支援密文就不送：FAIL-CLOSED，沒有明文後備。
- 金鑰在 USB：秘密金鑰不經 API 上傳、不做雲端備份。
- 拔除即清除：中止傳輸、白屏、抹除記憶體明文。
- 分級說清楚：L1 本期交付、L2 視端點能力、L3 不承諾。

## 1. 這是什麼（以及不是什麼）

4. 將密文與評估金鑰（evk / Galois / Relin Keys）送往已宣告密文能力之端點。
5. 接收密文結果，USB 在位時於本機解密並顯示。

HEShell **不訓練、不微調**基礎語言模型，**不實作**底層同態加密密碼學基元。

## 2. 能力分級（禁止混稱）

| L3 | 任意閉源 API 密文即時生成 | 密文 | 任意商用 LLM 直接解讀密文 | **非現行科技**：嚴禁承諾，不列入 v1 驗收與 Roadmap |

## 3. 延遲預期與介面規範

研究引用（非本產品 SLA；出處 [待確認]）：README 原稿依「2026 年公開密碼學與硬體加速研究」記載，以 CKKS 或 TFHE/FHEW 對約 8B 參數模型做端到端密文推論，相較明文約有 10^4 量級運算代價；短序列（≤ 64 tokens）延遲約數十秒至數分鐘；單一上下文狀態向量可能由數十 KB 膨脹至數十至數百 MB。

- 必須提供階段指示器：金鑰封裝中 → 密文傳輸中 → 密文同態運算中 → 密文下載中 → 本機解密驗證，並明示批次等待時間。

## 5. USB 狀態機

    DISCONNECTED → ATTACHED_IDLE → SESSION_ACTIVE → DECRYPTING → DISPLAYING_PLAINTEXT
          ▲                                                               │
          └──────────────────── 任意狀態：USB 拔除 ─────────────────────────┘

USB 拔除（緊急阻斷）：

1. 立即中止網路傳輸與解密運算
2. GUI 以空白填滿，抹除畫面明文
3. 對明文、對話快取、中介變數緩衝區零值抹寫（Zeroize / memset_s）
4. 銷毀通往該 USB 的 Context Handle
5. 禁止自磁碟快取或暫存區還原明文

工程門檻：中斷信號延遲與白屏／抹寫完成 ≤ 50 ms（驗收門檻，對外承諾 [待確認]）。

金鑰位置：sk 由 USB 生成並留存於 USB 邊界，不經 API 上傳。解密於「USB 驅動邊界或本地受限環境」執行之細節 [待確認]（是否需導出 sk）。

## 6. HE API 介面契約

殼層不自行實作密碼原語，依下列契約消費外部 HE 服務或本機 HE 模組（欄位值皆為示例）：

- A. `POST /v1/he/session/init`：建立會話（scheme、params、client_id）；回傳 session_id、public_key_ref、所需評估金鑰。sk 永不經此 API 上傳。
- B. 本機密文封裝：由本機 USB 驅動搭配本機 HE Client Engine 執行，不經遠端未受信任伺服器。
- C. `POST /v1/he/inference/dispatch`：送出密文、評估金鑰、`target_model_capability`、`max_computation_depth`；回傳 task_id 與 `estimated_latency_sec`（範例值，非承諾）。
- D. `GET /v1/he/inference/result/{task_id}`：取回密文結果、consumed_depth、proof_of_execution。
- E. 本機解密：僅 USB 在位時執行；USB 離線則硬體拒絕並拋錯。

錯誤碼：

| 錯誤碼 | 常數 | 行為 |
| :--- | :--- | :--- |
| HE_001 | ERR_USB_MISSING | 停止連線，清空工作區 |
| HE_002 | ERR_CAPABILITY_UNSUPPORTED | 主動熔斷，嚴禁降級送出明文 |
| HE_003 | ERR_PLAINTEXT_LEAK_GUARD | 輸出管道含非密文資料，硬中斷 |
| HE_004 | ERR_SESSION_MISMATCH | Session Key ID 不符，拒絕解密 |
| HE_005 | ERR_CIPHERTEXT_CORRUPTED | 雜湊錯誤或噪聲預算耗盡，推論失敗 |
| HE_006 | ERR_USB_PREMATURE_EJECT | 途中拔除，全域記憶體洗刷 |

## 7. 路由規則（FAIL-CLOSED）

1. **絕不自動降級**：端點不支援密文推論時，不提供「改以明文發送？」選項，請求直接無效。
2. **能力宣告白名單**：端點須提供經伺服器私鑰簽章之 Capability Manifest，載明支援方案（CKKS / BFV / TFHE）、最高乘法深度、密文 I/O 支援證明。
3. **明文審查閘門**：出境 Payload 若非標準密文結構或含自然語言明文字元，Socket 立即關閉。

## 8. 威脅模型摘要

可信任邊界：本機 USB 安全硬體、受 mlock 保護之 HEShell 核心程序。  
不可信任：宿主 OS 其他程序與 Swap、公共網路與代理、遠端推論伺服器、雲端日誌與計費端點。

| 編號 | 威脅 | 緩解 |
| :--- | :--- | :--- |
| TM-01 | 惡意伺服器竊聽 | 傳輸與運算為 HE 密文；伺服器僅持 evk，不持 sk |
| TM-02 | 拔除後殘留明文 | 拔除即 memset_s、白屏、無磁碟明文快取 |
| TM-03 | Swap/Pagefile 洩漏 | mlock / VirtualLock |
| TM-04 | 日誌與 Crash Dump 外洩 | 僅數值指標；封鎖 Full Memory Dump |
| TM-05 | 評估金鑰逆向 | 依 HE 標準參數（至少 128-bit 經典安全強度） |
| TM-06 | 中間人偽造能力宣告誘導降級 | 強制 FAIL-CLOSED，無明文回退路徑 |

## 9. 開發里程碑與驗收

里程碑（內部排程，非對外交期）：M1 硬體金鑰介面與安全記憶體 → M2 外部 HE API 整合 → M3 零洩漏路由器與 UI 狀態機 → M4 端到端密文推論整合與故障驗收。

本專案不以「串接任一公有 API 並秒回文字」作為驗收標準。驗收 Gate：

1. 金鑰邊界：拔除 USB 時解密回 HE_001，畫面與記憶體無明文；出境封包不含 sk。
2. 出境明文清零：封包捕獲不得出現任何自然語言片段。
3. 非相容端點中斷：路由至一般商用 LLM（L0）必須回 HE_002，嚴禁以明文降級成功。
4. 拔除白屏與抹寫：≤ 50 ms 白屏並 memset_s；Dump 檢查明文命中數為 0。
5. 日誌審計：執行紀錄、Crash Dump、路由追蹤檔明文出現率 0%。
