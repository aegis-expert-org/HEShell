## 2. 郵件文案

### 主旨
「加密 AI」只加密傳輸還不夠：神盾殼 HEShell 的分級與 FAIL-CLOSED 原則

### 預覽文字
L0 不算隱私；端點不支援密文就拒絕；拔掉 USB，畫面與記憶體明文立即清除。

### 內文結構

**① 開場**
傳輸層加密（TLS／HTTPS）下，伺服器端仍是明文，因此 HEShell 不把它當作隱私賣點【事實錨點：《P04》／§4 L0–L3 分級表 L0】。

**② 產品是什麼**
HEShell 是 AEGIS（`aegis.expert`）規劃中的本機 AI 安全殼層；它不訓練模型，也不自行實作密碼學基元，負責的是金鑰邊界、密文路由與本機明文防護【事實錨點：《P04》／§3 第 1 段】。

**③ 能力分級（對外說明必須照此）**
- L1 指定 HE API 固定電路密文運算（Embedding 比對、距離計算、數值評分與分類）：本期交付
- L2 端點密文模型推論：條件交付，只限具備明確能力宣告的端點
- L3 任意閉源商用 LLM 直接處理密文並即時生成：非現行科技，不承諾
【事實錨點：《P04》／§2 可保留內容「L0–L3 能力分級」；§4 分級表】

**④ 四項防護設計**
1. FAIL-CLOSED：沒有「改送明文」的後備路徑；出境封包若含自然語言明文字元，就強制關閉連線（`HE_003`）【事實錨點：《P04》／§4 第 2 點】
2. USB 硬體金鑰邊界：硬體憑證與非對稱挑戰握手；每次對話產生 Session【事實錨點：《P04》／§4 第 3 點】；sk 不會離開 USB；明文不會送到外部的 HE Provider【事實錨點：主 PMO 2026-11-13 指示／HEShell 阻斷事項釐清】
3. 本機記憶體防護：以 `mlock`／`VirtualLock` 防止明文寫入 Swap/Pagefile【事實錨點：《P04》／§4 第 5 點】
4. 零明文日誌：封鎖 Full Memory Dump【事實錨點：《P04》／§4 第 6 點】

**⑤ 範圍說明**
一般雲端 AI 聊天 API 不能直接處理密文（L3），HEShell 會拒絕這類路由【事實錨點：《P04》／§7 FAQ 第 1 題】。價格、硬體規格與上線時程目前尚未公布【事實錨點：《P04》／§7 FAQ 最後一題】。
